# Session: Life OS — SPA shell merging The Day + The Edit

## What shipped
One app, one server. `projects/life-os/serve.py` composes **The Day**
(`day-planner/planner.html`) and **The Edit** (`style-feed/feed.html`) into a
single-page app with a top tab bar (THE DAY · THE EDIT · MONEY[disabled]). No
iframes — one document, shared in-page state. Verified live on :8800: both views
render, tab switch toggles `#view-day`/`#view-edit` + updates `#hash`, calendar
shows 33 live events, The Edit shows 1018 cards, **zero console errors**, state
preserved across tab switches.

Annabel chose **true SPA merge** over the iframe-shell I recommended.

## How the merge works (the non-obvious parts)
- Both modules already share identical design tokens AND have **zero element-id
  overlap** → `document.getElementById` just works in the merged document.
- The Edit's JS is already IIFE-wrapped (no global leak). The Day's globals stay
  top-level. No JS collision.
- Only **9 CSS class collisions** (.acts .chip .empty .kicker .meta .on .out
  .row .tag) → solved by `scope_css()` prefixing each module's CSS under its
  `#view-*` section (recurses @media; leaves @keyframes/@font-face alone;
  maps body/html/:root → the section). Has a `--selfcheck` unit test.
- `serve.py` composes at request time from the canonical files, so The Day stays
  hand-authored and The Edit stays generated by `build_feed.py` — neither rots.
- Backends reused wholesale: imports both projects' `serve.py` via importlib
  under unique names (both are literally named serve.py), subclasses The Day's
  Handler. Routes: `/`=SPA, `/api/*`=The Day, `/feedback`+`/img`=The Edit.
  The Day's `THEDAY_KEY` gate now guards the whole app (one private link).

## Run it
`python3 projects/life-os/serve.py` (from AI-OS root, or `cd projects/life-os`).
Port 8800. Gated by THEDAY_KEY (in day-planner/.env): open `/?k=<key>` once to
set the cookie. Preview server name: `life-os`.
