# Proposal Structure

Use this for website refresh proposals and related client scope.

## Recommended Sections

1. Title: `<Client>: Website + Next Steps Proposal`
2. Review link or shipped work summary.
3. Phase 1: public website, fixed scope or already completed work.
4. Phase 2: backend, admin, workflow, content, or launch work that depends on
   discovery.
5. Estimate table with honest ranges.
6. Running total or budget guardrail if useful.
7. Optional add-ons, separated from core scope.
8. Terms: rate, payment, hosting/subscriptions, estimates.
9. Next steps.
10. Short note on estimates when discovery affects final billable time.

## Pricing Pattern

- Known website build or refresh: fixed fee when the scope is already done or
  tightly defined.
- Backend/vendor/admin coordination: hourly, capped block, or range until the
  tools and responsibilities are confirmed.
- Discovery meeting: priced or included explicitly, not hidden.
- Hosting and third-party subscriptions: show as ongoing client-paid costs.
- If there is a spending ceiling, say Annabel will flag before crossing it.

## Copy Rules

- Be direct and plain.
- Avoid salesy filler like "no surprises" when the factual process already gives
  reassurance.
- Avoid overexplaining every line item.
- No dashes as punctuation in Annabel/client-facing copy.
- If a stakeholder is the payer or approver, name the approval dependency
  accurately.

## Fit And QA

- Two pages is ideal for a small website refresh proposal.
- Three pages is acceptable only if the scope is genuinely larger.
- Avoid orphaned signatures or a final tiny page.
- Tables must be readable and not split awkwardly.
- Logo and brand color should support the document, not overpower it.
