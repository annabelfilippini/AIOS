# HTML Preview Quality

Use this before creating or polishing a static website mockup. The goal is a
credible client-review preview, not a generic generated landing page.

## Start With Direction

Pick one visual direction before coding:

- Premium clinical: calm, restrained, editorial, trust-heavy.
- Warm human clinic: approachable, founder-led, more texture and real people.
- Health-tech: crisp, product-aware, but still specific to the client's brand.
- Local service business: practical, clear, proof-led, not startup cosplay.

Name the direction in the project notes or handoff. If no direction is chosen,
pause and choose one from the client evidence.

## Preserve Identity-Bearing Assets

Before changing the design, identify what must survive from the current site:

- Original fonts or closest available webfont equivalents.
- Logo treatment, colors, and spacing cues that already feel recognizable.
- Images that explain the service or create trust, even if the surrounding
  section needs better layout.
- Human images that make the business feel real, especially clinical, founder,
  staff, treatment, workspace, or local context photography.
- Section concepts that are strategically useful, such as a tech-enabled clinic
  image, provider story, process visual, or patient pathway.

Do not replace necessary images with random stock or generated-looking visuals.
If an original image is weak but important, keep the concept and improve the
crop, framing, treatment, caption, or placement first.

Do not change the font stack just to make the mockup feel more polished. Inspect
the current site's CSS or rendered styles and reuse the original fonts when
possible. If the font cannot be loaded locally, use the closest fallback and
name that substitution in the handoff.

## Avoid AI-Generated Tells

Watch for these patterns and remove them during the polish pass:

- Blue/white SaaS palette used because the client is medical or technical.
- Repeating card grids with the same border, radius, shadow, and spacing.
- Huge hero plus right-side rounded image card plus three metric chips.
- Generic trust strips: "licensed providers," "personalized plan," "secure."
- Pill buttons everywhere, especially when the brand is more editorial or local.
- Vague section labels: "How it works," "Why choose us," "Built for you."
- Decorative gradients, radial glow backgrounds, and abstract blobs.
- Stock-feeling people images that do not match the client, city, or service.
- Internal preview labels, audit notes, implementation notes, or TODO language.
- Copy that could describe any competitor after swapping the logo.

## Build For The Client's Reality

Anchor the preview in the real business:

- Use the client's actual logo, font stack, color cues, typography direction,
  photos, staff names, services, location, portal links, and hours when
  available.
- Let one or two strong existing assets drive the design instead of inventing a
  whole new brand system.
- Preserve what is recognizable if the client already has brand equity.
- Show missing assets as deliberate placeholders only when the handoff names
  exactly what the client must provide.

## Layout Standards

Before calling a preview ready:

- Give the page a clear hierarchy: one primary promise, one primary CTA, one
  secondary CTA, and section pacing that does not feel like a template stack.
- Vary section composition. Mix editorial copy, split layouts, proof, process,
  service detail, and FAQs only when each earns its place.
- Use cards only for repeated items that benefit from comparison. Do not turn
  every section into cards.
- Keep buttons, nav, type, imagery, and spacing proportionate on mobile.
- Make the first viewport feel like the actual future site, not a moodboard or
  audit report.
- Remove any content that explains the redesign instead of being the redesign.

## Copy Standards

- Keep claims inside the approved claims matrix, especially for health,
  wellness, finance, legal, or pricing-sensitive sites.
- Prefer specific, plain language over inflated positioning.
- Do not use dashes as punctuation in client-facing copy.
- Remove redundant proof if the layout already communicates it.
- Replace generic phrases with client-specific nouns.

## Visual QA

Always inspect the rendered page before sharing:

- Side-by-side current-site and preview check for preserved fonts and necessary
  images.
- Desktop screenshot.
- Mobile screenshot.
- Console check.
- Top, middle, and bottom scroll pass.
- Link and CTA check for nav, phone, email, booking, forms, and portals.

If Annabel says it looks AI-generated, do not defend the structure. Run another
polish pass using the tells list above.
