# /podcast-pressure-test

**When to use:** Before recording an episode. Develops and pressure-tests an idea while it's still cheap to change.

**How to use:** Paste this prompt, then describe the episode idea below. A few sentences is enough. The skill should talk with Marta first, push the idea, and only then produce recording bullets.

---

## Prompt to paste

```
/podcast-pressure-test

Episode idea:

[describe the idea — what's the topic, what's the angle, what made you want to record this one]

Talk with me about this as my private editor before you give me an outline.

I do not want a script. I want to leave with a sharper idea and a short set of bullets I can glance at while recording.

Do NOT start with long critique paragraphs.
Do NOT give me an essay about the shadow side of the idea.
Do NOT produce recording bullets until I answer your questions.

Start with only this:

1. MY QUICK READ
   2 to 4 sentences max.
   Tell me what you think the episode is really about underneath the topic.
   If there is a stronger, more alive version of the idea, name it plainly.

2. QUESTIONS FOR ME
   Ask 4 to 6 specific questions that will help me think.
   Keep each question short: 1 to 3 sentences max.
   Make them conversational, not academic.
   Ask questions that make me reach for real moments, examples, tensions, people, or memories.

   Your questions should cover some of these, but only where relevant:
   - Who is the listener in a specific moment?
   - What has this person already tried that has not worked?
   - What is the belief I want to loosen, complicate, or break?
   - What real story, image, body sensation, or moment would make this land?
   - Where might this idea accidentally become too easy, too noble, or too generic?
   - What have I said about this before, and what is new this time?
   - What part of this am I personally still practicing?

   Good question shape:
   - "Can you picture the person listening to this? Where are they, and what just happened before they hit play?"
   - "What is one moment from your own life where this idea stopped being theoretical?"
   - "Where does this idea get dangerous if someone takes it too far?"
   - "What sentence would you want someone to text a friend after hearing this?"

   Bad question shape:
   - long paragraphs with multiple abstract tensions
   - questions that sound like an essay prompt
   - broad questions like "What is your message?"
   - advice disguised as a question

3. WAIT
   Stop after the questions.
   Wait for my answers.

After I answer, give me this exact output:

1. RECORDING BULLETS
   8 to 12 bullets, not a script.
   These should be phrases I can glance at while recording so I do not forget the thread.
   Include:
   - the listener
   - the belief I'm working on
   - the visceral moment
   - the central question
   - the 3 to 5 turns the episode should take
   - the closing line or closing question

2. WHAT WE SHARPENED
   3 to 5 bullets naming the sharper thought that came out of our conversation.

3. WHAT NOT TO SAY
   3 bullets naming the tempting generic version, over-explained tangent, or old frame I should avoid.

4. MEMORY UPDATE
   Write 3 to 6 bullets for content-memory.md:
   - episode topic / working title
   - central question
   - strongest visceral image or moment
   - listener this was for
   - threads to reuse later in speaking
   - threads to avoid repeating too soon

5. SAVE TO MEMORY
   If project memory is enabled, update your project memory now with the durable parts of the MEMORY UPDATE.
   Remember only Marta's public thought work: episode themes, recurring questions, voice preferences, audience insights, and speaking reuse.
   Do not remember client-identifying details, private session material, or anything Marta explicitly says not to save.
   If you cannot directly update memory or content-memory.md, say: "I can't directly update the file from here, but here is the exact memory block to save."

End with: ONE line — record this as-is, revise the angle first, or sit with it another week. Be honest.
```

---

## Notes on running this

- Run this *before* you sit down to record, ideally a day or two earlier. The "sit with it another week" verdict is real and worth listening to.
- If the answer to "who is this for" is anything like "anyone going through hard things," push back and ask Cowork to narrow it. Generic listener = generic episode.
- The questions are the point. The first answer should feel like the beginning of a conversation, not a finished critique.
- If Cowork starts producing paragraphs, paste: "Shorter. Ask me specific questions first."
- After the final output, Cowork should update project memory if memory is enabled. If it cannot directly update memory or `content-memory.md`, paste the MEMORY UPDATE into `content-memory.md` so speaking prep can reuse the thread later.
- After recording, Marta can come back to the same chat and ask: "Did I stay with the thread we built?" Use the recording bullets as the comparison point.
