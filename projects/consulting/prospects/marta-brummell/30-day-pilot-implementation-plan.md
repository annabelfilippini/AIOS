## Pilot Wedge

Build a private content and speaking thought-partner workflow, plus one practical improvement to Marta's existing session recording to follow-up process.

The first workflow should help Marta pressure-test one real upcoming piece before it goes to Grace or an audience:

- podcast idea
- talk outline
- episode transcript
- newsletter draft, if she chooses to include one

The workflow should return audience clarity, emotional arc, strongest moments, weak or abstract sections, stronger opening/closing options, and specific notes Marta can pass to Grace.

## Why This Is The Wedge

Marta is already using AI in a high-trust way for session summaries and email drafts. The opportunity is not beginner AI adoption.

Discovery shows the sharper bottleneck is quality control before production:

- Grace supports production but does not provide rigorous critical feedback.
- Marta's speaking opportunities are increasing.
- She wants talks to land as visceral experiences, not just concept teaching.
- Her podcast audience is somewhat undefined.
- The current session recording flow has an annoying cutoff issue.

This pilot should protect Marta's voice and judgment while giving her a better review loop.

## Success Signal

Pick one primary signal during scope confirmation:

- Marta uses the workflow on at least two real pieces in 30 days.
- One talk, podcast episode, or post-recording handoff becomes meaningfully sharper because of the review.
- Session follow-up becomes easier because recording and draft creation require fewer manual restarts or cleanup steps.

Avoid measuring this only in hours saved. The stronger metric is confidence and quality: did the piece land better, and did the workflow earn repeat use?

## What Annabel Needs From Marta

Minimum:

- one upcoming podcast idea, talk outline, or transcript
- 2-3 examples of past work Marta considers strong
- current session recording tool/process
- confirmation of what Grace owns today
- explicit rules for what the AI workflow may draft, critique, summarize, or never touch
- approval on where any prompts or notes should live

Optional, only if Marta is comfortable:

- anonymized examples of session follow-up emails
- one prior talk or podcast transcript
- current handoff notes to Grace

Do not request raw sensitive client session material unless there is a clear privacy rule and a concrete need.

## 7-Day Build Plan

### Day 1 — Scope Confirmation

- Confirm the first real use case: podcast idea, talk outline, transcript, or session follow-up.
- Confirm whether the recording fix is part of the first week or a parallel recommendation.
- Write the non-goals: no publishing, no replacing Grace, no auto-sending client emails.

### Day 2 — Context Draft

- Draft Marta's working context: audience, voice, offers, standards, approval rules, and recurring content patterns.
- Mark assumptions separately from confirmed facts.
- Identify where examples are missing.

### Day 3 — First Skill Draft

Create the first workflow as a plain-language skill or prompt:

- input: one outline, transcript, or idea
- output: critique, audience read, emotional arc, strongest moments, weak spots, Grace handoff notes, and next edit
- guardrail: Marta decides what changes

### Day 4 — Real Input Test

- Run the workflow on one real piece Marta chooses.
- Capture what felt accurate, generic, too sharp, too soft, or off-voice.
- Tune the prompt/context from Marta's edits.

### Day 5 — Existing-Tool Placement

- Put the workflow in the tool Marta will actually use.
- Keep the action simple: paste the material, run the named workflow, review the output.
- Document any recording/session-summary recommendation without pretending account setup is complete.

### Day 6 — Handoff Note

- Write a one-page "how this works" note.
- Include when to use it, what to paste, what the output means, and what still requires Marta's judgment.
- Keep it somewhere Marta will find it, not in a new dashboard.

### Day 7 — Live Run

- Run a second real piece with Marta.
- Watch where she hesitates or ignores the output.
- Schedule or reconfirm the 30-day review.

## Human Review Rules

- The workflow may critique, summarize, draft, and suggest.
- Marta approves all client-facing, audience-facing, or Grace-facing output.
- The workflow must not publish, send, schedule, or contact anyone.
- Client session content should be minimized, anonymized where possible, and handled only with explicit approval.
- The workflow should support Grace's production work, not silently replace it.

## What Not To Build

- No CRM.
- No membership scaling system.
- No Circle automation.
- No newsletter expansion plan until Marta explicitly chooses that lane.
- No public lead magnet or site changes in this pilot.
- No dashboard or database the client has to remember to maintain.

## 30-Day Review Agenda

- Which pieces did Marta run through the workflow?
- Did it make podcast, speaking, or Grace handoff work sharper?
- Did anything feel generic, wrong, or intrusive?
- Did the recording/session-summary flow improve?
- What should be tuned, expanded, or removed?
- Is there a private or public case-study asset worth capturing?
- Does Marta want a second workflow, a maintenance retainer, or no continuation?
